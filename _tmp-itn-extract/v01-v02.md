# ITN/ONR Nº 001 — Especificação Técnica: Recibo (v1.0) e Certidão Estruturada (v2.0)

**Fontes analisadas:**
- `v1.0\Anexo_V_-_EspecificacaoTecnica_ReciboEstruturado.txt` (Anexo V, versão doc 1.0.0, 09/03/2021)
- `v2.0\Anexo_IV_-_EspecificacaoTecnica_CertidaoEstrutura.txt` (Anexo IV, versão doc 2.0.0, 10/03/2021)
- XMLs de template e exemplo em ambas as versões

**Contexto:** Documentos do **PEER Nacional** (Pedido Eletrônico Estruturado para Registro). O cartório emite o artefato estruturado em decorrência de atos praticados com base em Extratos originados de instrumentos públicos, particulares, administrativos e títulos de crédito, em formato importável.

---

## 1. Estrutura XML completa (hierarquia de tags)

```
<?xml version="1.0" encoding="utf-8"?>
ROOT
└── CONTRATO
    ├── CNS
    ├── PROTOCOLO_SAEC
    ├── NUMERO_PRENOTACAO
    ├── DATA_REGISTRO
    ├── VALOR_TOTAL_CUSTAS          ← somente v1.0 (Recibo)
    └── ATOS_PRATICADOS
        └── ATO_PRATICADO           (0..N — lista repetível)
            ├── CODIGO_ATO
            ├── NUMERO_MATRICULA
            ├── NUMERO_ATO
            └── DESCRICAO_ATO
```

### Cardinalidade inferida

| Nó | Cardinalidade | Observação |
|---|---|---|
| `ROOT` | 1 | Raiz do documento |
| `CONTRATO` | 1 | Um contrato/pedido por arquivo |
| `CNS` | 1 | Identificação do cartório |
| `PROTOCOLO_SAEC` | 1 | Vínculo com contrato eletrônico do interessado |
| `NUMERO_PRENOTACAO` | 1 | Prenotação gerada pelo cartório |
| `DATA_REGISTRO` | 1 | Data do registro |
| `VALOR_TOTAL_CUSTAS` | 1 (v1.0) | Ausente em v2.0 |
| `ATOS_PRATICADOS` | 1 | Container da lista |
| `ATO_PRATICADO` | 1..N | Pelo menos 1 ato esperado em uso real; spec não define mínimo formal |

### Encoding e declaração

- Declaração XML: `<?xml version="1.0" encoding="utf-8"?>`
- Encoding dos exemplos: **UTF-8**

## 2. Tabela completa de campos

> **Nota sobre obrigatoriedade:** Os TXT **não marcam explicitamente** campos como obrigatório/opcional. A coluna **Obrigatório** combina: presença no template XML, semântica de negócio e exemplos oficiais.

### 2.1 Nível `CONTRATO`

| Tag | Tipo (spec) | Tamanho | Obrigatório | Observação |
|---|---|---|---|---|
| `CNS` | Numérico | *não especificado* | **Sim** | Número do CNS do cartório. Exemplo: `111111`. |
| `PROTOCOLO_SAEC` | Alfanumérico | *não especificado* | **Sim** | Protocolo gerado pelo SAEC/Central/Cartório para vincular ao contrato eletrônico do interessado. Formato de exemplo: `AC0001234` (comentário XML: `ACXXXXXXXXX`). Em v2.0 substituiu nomenclatura histórica `PROTOCOLO_ARISP`. |
| `NUMERO_PRENOTACAO` | Numérico | *não especificado* | **Sim** | Número da prenotação gerada pelo cartório. Exemplo: `446112`. |
| `DATA_REGISTRO` | Data | *não especificado* | **Sim** | Data do registro do ato praticado. Formato nos exemplos: `YYYY-MM-DD` (ex.: `2021-03-22`). |
| `VALOR_TOTAL_CUSTAS` | Monetário | *não especificado* | **Sim (v1.0)** / **N/A (v2.0)** | Valor total das custas. Formato nos exemplos/comentários: decimal com 2 casas (`0.00`). **Exclusivo do Recibo v1.0.** |
| `ATOS_PRATICADOS` | `List<ATO>` | — | **Sim** | Container da lista de atos praticados. |

### 2.2 Nível `ATO_PRATICADO`

| Tag | Tipo (spec) | Tamanho | Obrigatório | Observação |
|---|---|---|---|---|
| `CODIGO_ATO` | Tabela de domínio | — | **Sim** | Código do ato praticado. Deve pertencer à tabela 2.2.1 ATOS. |
| `NUMERO_MATRICULA` | Inteiro | *não especificado* | **Sim** | Número da matrícula/registro do imóvel. Exemplo: `168762`. |
| `NUMERO_ATO` | Inteiro | *não especificado* | **Sim** | Número sequencial do ato na matrícula. Enviar **apenas o número**, sem prefixo textual. Ex.: para `Ab.0`, `R.1`, `AV.2` → enviar `0`, `1`, `2`. Exemplos XML: `3`, `2`, `26`. |
| `DESCRICAO_ATO` | Alfanumérico | **200** | **Condicional** | Obrigatório quando `CODIGO_ATO = 999` (Outros). Para demais códigos, pode ficar vazio nos exemplos. Descreve o tipo de ato (ex.: "Retificação administrativa", "averbação de casamento"). |

## 3. Tabelas de domínio completas

### 3.1 ATOS (`CODIGO_ATO`) — tabela 2.2.1

Presente **integralmente** em v1.0 e v2.0 (conteúdo idêntico nos TXT e comentários XML).

| Código | Descrição do ato |
|---:|---|
| **1** | Venda e compra |
| **2** | Hipoteca |
| **3** | Alienação fiduciária |
| **4** | Portabilidade |
| **6** | Averbação de CCI |
| **8** | Alienação Fiduciária para Abertura de Limite de Crédito |
| **9** | Compromisso de venda e compra |
| **10** | Doação |
| **18** | Aditamento de cédula |
| **19** | Penhor |
| **20** | Registro da cédula |
| **999** | Outros |

#### Códigos ausentes na tabela (lacunas numéricas)

Os seguintes códigos **não constam** na especificação e devem ser tratados como **inválidos** até eventual ampliação oficial:

`5`, `7`, `11`, `12`, `13`, `14`, `15`, `16`, `17`, e qualquer valor fora da lista acima exceto os listados.

#### Uso de `999 — Outros`

- Quando o ato praticado não se enquadra nos códigos padronizados.
- Exige preenchimento de `DESCRICAO_ATO` com texto livre (até 200 caracteres).
- Exemplo oficial: `DESCRICAO_ATO = "NOME DO TIPO DE ATO"`.

## 4. Regras de negócio e validações inferidas

### 4.1 Propósito e escopo

| Regra | Detalhe |
|---|---|
| **Emissor** | Oficial de Registro de Imóveis |
| **Gatilho** | Atos praticados com base em Extratos de instrumentos públicos, particulares, administrativos e títulos de crédito |
| **Consumo** | Formato estruturado para **importação** por sistemas do PEER/interessado |
| **Vínculo eletrônico** | `PROTOCOLO_SAEC` correlaciona o recibo/certidão ao contrato eletrônico do interessado no ecossistema SAEC |

### 4.2 Identificação do cartório e do pedido

| Campo | Regra inferida |
|---|---|
| `CNS` | Deve corresponder ao CNS do cartório emissor; formato numérico |
| `PROTOCOLO_SAEC` | Alfanumérico; padrão ilustrado `AC` + dígitos (`AC0001234`). Validar presença e não-vazio |
| `NUMERO_PRENOTACAO` | Identificador interno da prenotação no cartório; numérico |
| `DATA_REGISTRO` | Data efetiva do registro; validar formato ISO `YYYY-MM-DD` conforme exemplos |

### 4.3 Lista de atos (`ATOS_PRATICADOS`)

| Regra | Detalhe |
|---|---|
| **Multiplicidade** | Um pedido pode conter **vários** `ATO_PRATICADO` (exemplo oficial com 3 atos) |
| **Mesma matrícula** | Vários atos podem referenciar a **mesma** `NUMERO_MATRICULA` no mesmo arquivo |
| **Tipos distintos** | Cada item pode ter `CODIGO_ATO` diferente na mesma remessa |
| **Ordem** | Spec não define ordenação obrigatória; preservar ordem de registro é recomendável |

### 4.4 Regras por campo de ato

| Campo | Validação inferida |
|---|---|
| `CODIGO_ATO` | Enum fechado (tabela 3.1). Rejeitar códigos fora da lista |
| `NUMERO_MATRICULA` | Inteiro positivo; sem máscara ou formatação nos exemplos |
| `NUMERO_ATO` | Inteiro; representa somente a parte numérica do identificador do ato na matrícula (`R.3` → `3`). Não enviar prefixos `Ab.`, `R.`, `AV.` |
| `DESCRICAO_ATO` | Máx. **200** caracteres. **Obrigatório** se `CODIGO_ATO = 999`. **Opcional/vazio** para demais códigos (confirmado pelos exemplos com `DESCRICAO_ATO` vazio para códigos 1 e 19) |

### 4.5 Regras financeiras (somente v1.0 — Recibo)

| Regra | Detalhe |
|---|---|
| `VALOR_TOTAL_CUSTAS` | Valor monetário agregado das custas do registro |
| Formato | Decimal com separador ponto e 2 casas: `0.00` |
| Semântica | Campo de **totalização** no nível do contrato, não por ato individual |

### 4.6 Validações estruturais XML

| Validação | Detalhe |
|---|---|
| Raiz | Deve ser `ROOT` |
| Filho único de `ROOT` | `CONTRATO` |
| Tags desconhecidas | Não documentadas; evitar extensões não padronizadas |
| Elementos vazios | Templates usam tags vazias como placeholder; em produção, campos obrigatórios não devem ser enviados vazios |
| Comentários XML | Presentes nos templates (`<!-- ... -->`); não fazem parte do contrato de dados em produção |

### 4.7 Matriz condicional `DESCRICAO_ATO`

| `CODIGO_ATO` | `DESCRICAO_ATO` |
|---|---|
| `999` | **Obrigatório**, não vazio, ≤ 200 chars |
| `1`, `2`, `3`, `4`, `6`, `8`, `9`, `10`, `18`, `19`, `20` | **Opcional** (vazio permitido) |

## 5. Diferenças v1.0 (Recibo) vs v2.0 (Certidão Estruturada)

| Aspecto | v1.0 — Recibo Estruturado | v2.0 — Certidão Estruturada |
|---|---|---|
| **Anexo ITN** | Anexo **V** | Anexo **IV** |
| **Artefato** | Recibo do Registro de Imóveis | Certidão Estruturada do Registro de Imóveis |
| **Versão do documento** | 1.0.0 (09/03/2021) | 2.0.0 (10/03/2021) |
| **Campo `VALOR_TOTAL_CUSTAS`** | **Presente** (nível `CONTRATO`) | **Ausente** |
| **Campo `PROTOCOLO_SAEC`** | Já nomeado `PROTOCOLO_SAEC` no TXT/XML v1.0 | Changelog v2.0 registra renomeação de `PROTOCOLO_ARISP` → `PROTOCOLO_SAEC` (legado) |
| **Código `999 — Outros`** | Presente no TXT v1.0 e XML v1.0 | Changelog v2.0 cita **inserção** do item 999; conteúdo já existia em v1.0 |
| **Classe `CONTRATO`** | CNS, PROTOCOLO_SAEC, NUMERO_PRENOTACAO, DATA_REGISTRO, ATOS_PRATICADOS, **VALOR_TOTAL_CUSTAS** | CNS, PROTOCOLO_SAEC, NUMERO_PRENOTACAO, DATA_REGISTRO, ATOS_PRATICADOS |
| **Classe `ATO`** | Idêntica | Idêntica |
| **Tabela de domínio ATOS** | Idêntica (13 códigos) | Idêntica (13 códigos) |
| **Estrutura XML de atos** | Idêntica | Idêntica |
| **Exemplo XML** | Inclui `VALOR_TOTAL_CUSTAS` | Sem campo financeiro |

### Resumo para implementação

- **Parser único** pode tratar ambas as versões com o mesmo modelo de `ATO_PRATICADO`.
- Diferenciar por presença/ausência de `VALOR_TOTAL_CUSTAS` no nível `CONTRATO`.
- v2.0 é semanticamente uma **certidão** (sem totalização de custas); v1.0 é um **recibo** (com custas).

### Linha do tempo de revisão (v2.0)

| Data | Versão | Alteração |
|---|---|---|
| 09/03/2021 | 1.0.0 | Versão inicial certidão estruturada |
| 10/03/2021 | 2.0.0 | `PROTOCOLO_ARISP` → `PROTOCOLO_SAEC`; inclusão formal do código `999` |

## 7. Checklist de validação para desenvolvedor

```
[ ] XML well-formed, encoding UTF-8
[ ] Raiz ROOT → CONTRATO único
[ ] CNS numérico preenchido
[ ] PROTOCOLO_SAEC alfanumérico preenchido (padrão AC...)
[ ] NUMERO_PRENOTACAO numérico preenchido
[ ] DATA_REGISTRO formato YYYY-MM-DD
[ ] v1.0: VALOR_TOTAL_CUSTAS presente, decimal 0.00
[ ] v2.0: VALOR_TOTAL_CUSTAS ausente
[ ] ATOS_PRATICADOS com ≥1 ATO_PRATICADO
[ ] CODIGO_ATO ∈ {1,2,3,4,6,8,9,10,18,19,20,999}
[ ] NUMERO_MATRICULA inteiro
[ ] NUMERO_ATO inteiro (somente número, sem prefixo Ab./R./AV.)
[ ] Se CODIGO_ATO=999 → DESCRICAO_ATO obrigatório, max 200
[ ] Se CODIGO_ATO≠999 → DESCRICAO_ATO pode ser vazio
```

## 8. Lacunas da especificação (não documentadas nos TXT)

Itens **não definidos** nos arquivos analisados — tratar com cautela ou confirmar com ONR:

| Tópico | Lacuna |
|---|---|
| Tamanho de `CNS` | Não especificado (ex.: 6 dígitos é convenção de mercado, não está no TXT) |
| Tamanho de `PROTOCOLO_SAEC` | Apenas exemplo `ACXXXXXXXXX` |
| Tamanho de `NUMERO_PRENOTACAO` / `NUMERO_MATRICULA` / `NUMERO_ATO` | Sem limite formal |
| Formato monetário | Apenas inferido (`0.00`); sem regra de arredondamento |
| Schema XSD | Não fornecido nos arquivos analisados |
| Obrigatoriedade formal | Não há coluna "obrigatório" na spec original |
| Namespace XML | Não utilizado nos exemplos |
| Assinatura digital / hash | Não mencionado |
| Múltiplos `CONTRATO` por arquivo | Não previsto (1 por `ROOT`) |
