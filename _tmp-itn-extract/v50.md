# PARTE A — PEER Tabelionato de Notas (PEER-TN) v5.0

## A.1 Visão geral e escopo

O **PEER-TN** é o Pedido Eletrônico Estruturado de Registro enviado pelo **Tabelionato de Notas** ao Registro de Imóveis (Lei 14.382/2022). Um documento XML pode conter **vários extratos eletrônicos** no mesmo contexto de negócio.

**Negócios suportados (TN v5.0):**

| Categoria | Valores |
|-----------|---------|
| Transmissão | `compra e venda`, `doação` |
| Crédito/parcelamento com garantia | **Somente** `parcelamento de pagamento` |
| Garantia | `hipoteca`, `alienação fiduciária` |

**Título de origem:** exclusivamente **Escritura Pública** (`IdEscrituraPublica`).

**Moeda:** todos os valores monetários em **R$**, formato `ValorMonetario` (`1234,56`).

## A.2 Notação UML e tipos elementares

| Notação | Significado XSD típico |
|---------|------------------------|
| `1` | `minOccurs="1" maxOccurs="1"` — obrigatório |
| `0..1` | opcional |
| `1..*` | `minOccurs="1" maxOccurs="unbounded"` |
| `0..*` | zero ou mais |
| **Agrupamento** | `xs:sequence` — todos os filhos na ordem |
| **Conjunto** | container com filhos repetíveis |
| **Opção exclusiva** | `xs:choice` — exatamente uma opção |
| **Opção não exclusiva** | `xs:choice` com `maxOccurs>1` ou regra de negócio “≥1 opção” |
| **Sequência** | ordem cronológica preservada (`NegociosJuridicosEAverbacoes`) |
| **Flag** | elemento vazio (`complexType` vazio) — presença = verdadeiro |
| **Referência** | valor referencia outro objeto (ex.: `IndiceRepresentacaoPessoa`) |

# PARTE B — PEER Instituição Financeira (PEER-IF) v5.0

## B.1 Visão geral e escopo ampliado

O **PEER-IF** cobre instrumentos particulares enviados por instituições financeiras. Um XML pode ter **vários extratos**; cada extrato pode ter transmissão, crédito/garantia **e/ou averbações**.

**Negócios suportados (IF v5.0):**

| Categoria | Valores |
|-----------|---------|
| Transmissão | compra e venda, doação |
| Crédito/parcelamento | financiamento imobiliário, empréstimo, abertura de limite de crédito, crédito de consórcio, parcelamento, sub-rogação de empréstimo/financiamento *(novação: citada na spec, **não** no XSD)* |
| Garantia | hipoteca, hipoteca estendida, alienação fiduciária, AF superveniente, AF estendida |
| **Averbações** | Cancelamento de garantia · Emissão CCI · Sub-rogação credor · Leilão negativo (ausência de lance 2º leilão) |

**Título de origem:** exclusivamente **InstrumentoParticular** (`IdInstrumentoParticular`).

**Regras de negócio IF:**
- CCI pode ir no extrato do contrato **ou** em extrato dedicado da cédula.
- Cancelamento de garantia pode ir no contrato **ou** no termo de quitação.
- `UsoExclusivoExpedidorEONR` substitui o antigo campo empreendimento (uso interno IF/ONR).

## C.4 Regras XSD v5.0 (checklist implementação)

1. **XSD 1.1** — suporte a `xs:assert` para regras condicionais (`outro` → `OutroValor`).
2. **elementFormDefault=qualified** — todos os elementos no namespace alvo.
3. **Cardinalidades** mapeadas de UML para `minOccurs`/`maxOccurs`.
4. **Opções exclusivas** = `xs:choice` (uma opção por choice).
5. **Sequência cronológica** = ordem fixa em `NegociosJuridicosEAverbacoes` (transmissão → crédito → averbação).
6. **Validação de padrões** — regex em `xs:pattern` para CPF, CNM, datas BR, valores monetários.
7. **Comprimento fixo** — CPF (14), CNPJ (19), CEP (9) via `xs:length`.
8. **Flag** — `complexType` vazio (elemento auto-fechado `<Imovel/>`).
9. **Assinatura** — tipo `Alfanumerico` no XSD; validação criptográfica XMLDSig é responsabilidade do pipeline ONR.
10. **Duplicata de arquivos** — `PEERTabelionatoNotas.xsd` ≡ `PEER_Tabelionato_Notas.xsd`; escolher um como referência.
11. **lote.xsd vs schema principal** — estruturas de lote **divergentes** (com/sem wrapper `Pedido`); confirmar com ONR qual é a vigente em produção.
12. **Namespace exemplos** — alinhar `PEER-IF/v1` (exemplos) vs `PEER/v1` (XSD) antes de validação automática.

## C.5 Evolução funcional v3.7 → v5.0 (highlights)

- **Lei 14.382/2022:** extrato eletrônico, declarações padronizadas, autenticidade/conformidade/arquivamento.
- **DOI/COAF:** `ComposicaoPagamento` (valores mutuamente excludentes) + `ComunicacoesPagamento` (SituacaoPagamento, ValorPagoAteDataNegocio) — requisitos Prov. CNJ 149/2024.
- **MNE:** matrícula notarial eletrônica (Prov. CNJ 100/2020).
- **Imóvel rural:** CCIR/SNCR/INCRA estruturados; CAT-SPU para laudêmio União.
- **Regime de bens / pactos:** Lei 14.382 art. 6º §3º (pacto antenupcial/convivência com registro auxiliar).
- **Leilão negativo:** averbação formal com dois leilões, comunicação devedores, resultado negativo (Lei 9.514/1997 art. 26-A).
- **Programas habitacionais:** PH-FGTS, PMCMV, PAR, origens FAR/FGTS etc. (IF).
- **TN simplificado:** foco em escrituras (compra/venda, doação, parcelamento+AF/hipoteca); sem averbações no perfil TN.

## C.7 Nota sobre TN v5.0 vs listas na documentação

A especificação textual TN lista **todos** os valores de `TipoNegocioJuridicoCreditoOuParcelamento` e `TipoNegocioJuridicoGarantia` (herança do modelo comum), mas o **XSD TN restringe** efetivamente a:

- Garantia: `hipoteca`, `alienação fiduciária`

Para validação de produção TN, **prevalece o XSD**.
